B) Exact json3 parsing approach

json3 shape — from yt-dlp --sub-format json3

{
  "events": [
    {
      "tStartMs": 1240,
      "dDurationMs": 3200,
      "segs": [{ "utf8": "hello ", "tOffsetMs": 0 }, { "utf8": "world", "tOffsetMs": 400 }],
      "wWinId": 1
    }
  ]
}

Source file is tmp/<id>/*.en.json3 or *.en.auto.json3. Glob and pick the first match.

Algorithm — src/transcript.ts:1

  1. Read + JSON parse as unknown. Guard top-level has events: unknown[], else throw TranscriptParseError.
  2. Iterate events. Skip where segs absent/null (header/formatting events with tStartMs: 0). Skip empty segs.
  3. Per segment: absoluteMs = event.tStartMs + segment.tOffsetMs — both integers; tOffsetMs is offset within the event. Do not use dDurationMs.
  4. Per word: utf8 may have leading/trailing spaces and be a partial word. Emit one TranscriptWord per seg where utf8.trim().length > 0: 
    { text: seg.utf8.trim(), startMs: absoluteMs, endMs: /* nextWord.startMs or event.tStartMs+event.dDurationMs */ }
    Infer endMs as nextWord.startMs (or event end for last seg) — conservative clip boundaries.
  5. Collapse: words: TranscriptWord[] sorted by startMs; fullText = words.map(w => w.text).join(" "); durationSeconds = lastWord.endMs / 1000.
  6. Timestamped transcript for LLM: chunk words into ~30s lines: [00:12] hello world … — derived from startMs, never model-generated.
  7. Edge cases: empty events → NoCaptionsError; file not found → NoCaptionsError; malformed JSON → TranscriptParseError. All local, zero model cost.

Parser output validation

words.length > 0, monotonically increasing startMs, durationSeconds > 0. Log word count + duration for debugging (never the key).

Request shape — src/llm.ts:1

  • Endpoint: POST https://openrouter.ai/api/v1/chat/completions
  • Headers: Authorization: Bearer ${OPENROUTER_API_KEY}, Content-Type: application/json, optional HTTP-Referer + X-Title
  • Body:
{
  "model": "minimax/minimax-m3:free",
  "messages": [
    { "role": "system", "content": "<system prompt — strict JSON, English only>" },
    { "role": "user",   "content": "<transcript + output schema + rules>" }
  ],
  "temperature": 0.2,
  "max_tokens": 4000,
  "response_format": { "type": "json_object" }
}

response_format: json_object forces JSON mode on routes that support it; prompt still demands raw JSON with no markdown fences as fallback.

System message (fixed): You are a YouTube distiller. You receive a full English transcript with [mm:ss] anchors. Return ONLY valid JSON matching the provided schema. No prose outside JSON, no markdown fences. English only. Moments within transcript duration, non-overlapping preferred, each 15–90s.
Transcript duration: 47:12 (2832s), 8234 words.
Transcript:
[00:00] ...
[00:31] ...

Task: produce JSON with:
- brief: 3-6 sentence summary of what the video actually covers (not generic hype).
- moments: 3-5 ranked highlights, each with startSeconds, endSeconds, title (hook, <=60 chars), reason (1 sentence).

Rules:
- startSeconds/endSeconds are integers, 0 <= start < end <= 2832, duration 15-90s.
- Sorted by rank 1..N (1 = best).
- No overlapping moments preferred; if unavoidable, keep <5s overlap.
- Return ONLY the JSON object.

JSON Schema demanded back

{
  "type": "object",
  "required": ["brief", "moments"],
  "additionalProperties": false,
  "properties": {
    "brief": { "type": "string", "minLength": 80, "maxLength": 800 },
    "moments": {
      "type": "array",
      "minItems": 3,
      "maxItems": 5,
      "items": {
        "type": "object",
        "required": ["rank", "title", "reason", "startSeconds", "endSeconds"],
        "additionalProperties": false,
        "properties": {
          "rank":         { "type": "integer", "minimum": 1, "maximum": 5 },
          "title":        { "type": "string", "minLength": 5, "maxLength": 60 },
          "reason":       { "type": "string", "minLength": 10, "maxLength": 200 },
          "startSeconds": { "type": "integer", "minimum": 0 },
          "endSeconds":   { "type": "integer", "minimum": 1 }
        }
      }
    }
  }
}

Extra semantic checks in schema.ts (not JSON Schema): start < end, 15 ≤ duration ≤ 90, end ≤ transcriptDurationSeconds, rank contiguous 1..N, non-empty titles/reasons.

D) Validation and what happens on malformed output

Principle One request already spent — do not spend a second to "fix" JSON. Validate strictly, fail loudly.

src/schema.ts:1 — validateDistillResult(raw: unknown, durationSeconds: number): DistillResult

1 · Pre-parse sanitization (local, zero cost)

Trim string, strip ```json / ``` fences via ^```(?:json)?\s*|\s*```$, trim again. JSON.parse in try/catch — on SyntaxError throw ValidationError with first 500 chars (never the key).

2 · Structural validation (no any)

Assert object, check brief string bounds, moments array 3..5, per-moment field presence + Number.isInteger ranges, then semantic rules above.

3 · On failure

Throw ValidationError with issues: string[] (all violations). pipeline.ts emits { phase: "analyze", status: "error", issues } and aborts before ffmpeg. CLI prints issues + hint: retry costs 1 more request or change MODEL_ID in config.ts:1. SSE sends event: error; UI shows retry button. No automatic retry that burns budget silently — retry is user-initiated only.

4 · On success: return typed DistillResult and proceed to clip.ts.

  • Temp dir: left on failure for debugging unless --clean; server auto-cleans after 30m.

F) Request counter — user always sees budget use

class RequestCounter {
  private n = 0;
  increment(): number { return ++this.n; }
  get value(): number { return this.n; }
  toString(): string { return `${this.n} request(s)`; }
  budgetString(): string { return `${this.n}/1000 today (limit is requests, not tokens)`; }
}
  • Ownership: instantiated once in pipeline.ts, passed to llm.ts. Only llm.ts calls increment() — immediately before each fetch (including fallbacks).
  • Visibility: every ProgressEvent carries requestCount. Final done event includes it. CLI prints Requests used: 1/1000 (1 per video) or 3/1000 (1 primary + 2 fallbacks). UI shows pill ● 1 request used — 999 remaining today (estimate; true daily count on dashboard).
  • Invariant: pipeline.ts asserts counter.value ≤ 3 at end (1 primary + 2 fallbacks). If >1 on success, warn — bug violating single-request design.

G) Progress event shape — how CLI and SSE consume it

Event type — src/types.ts:1

type PipelinePhase = "download" | "transcribe" | "analyze" | "clip" | "done";

interface ProgressEvent {
  phase: PipelinePhase;
  status: "start" | "progress" | "done" | "error";
  message: string;
  percent?: number;         // 0–100
  requestCount: number;
  timestamp: number;        // Date.now()
  result?: DistillResult & { clips: ClipInfo[] }; // only done:done
  error?: { code: string; details?: string; retryAfterSeconds?: number; issues?: string[] };
}
  • pipeline.ts exposes async function* run(url: string): AsyncGenerator<ProgressEvent> — preferred over EventEmitter for trivial forwarding.
  • Phases in order: download:start → done → transcribe:start/done → analyze:start → done|error → clip:start → progress (per clip) → done → done:done
  • Only analyze may increment requestCount.

CLI — src/cli.ts:1

[download] start — fetching video + captions…

[transcribe] done — 8234 words
[analyze] start — 1 request to minimax/m3:free (15K tokens)…
[analyze] done — brief + 4 moments (1 request used)
[clip] progress — cutting 1/4 "The hook title" [00:12–01:05]…

Loop: for await (const ev of pipeline.run(url)). ANSI colors manually (no heavy deps). On error → stderr + process.exit(1).

H) MVP cut line for a 90-minute live build

Assumption UI takes ~12 min and must not be cut. Leaves 78 min for the engine.

Must ship — in build order

  1. Project scaffold (5m): bun init, tsconfig.json strict, .gitignore, src/config.ts:1 with MODEL_ID, src/types.ts:1, src/counter.ts:1.
  2. yt-dlp wrapper (10m): src/yt.ts:1 — download + captions, temp dir, file discovery. Manual test with a known captioned video.
  3. json3 parser (10m): src/transcript.ts:1 — pure function + tiny hand-crafted fixture. Verify absoluteMs formula.
  4. Schema validator (8m): src/schema.ts:1 — unknown guards, bounds, fence stripping. Test good + malformed fixtures.
  5. LLM single request (15m): src/llm.ts:1 — one fetch, response_format: json_object, 429 fallback, 90s timeout, counter.
  6. ffmpeg cutter (8m): src/clip.ts:1 — spawn, -ss/-to, copy then re-encode fallback.
  7. Pipeline orchestration (10m): src/pipeline.ts:1 — wires 1–6, AsyncGenerator events, error mapping.
  8. CLI face (5m): src/cli.ts:1 — arg parse, event loop, pretty print, exit codes.
  9. Server face (7m): src/server.ts:1 — Bun.serve, SSE endpoint, static serving.
  10. UI (12m): public/index.html:1 — input, EventSource, progressive rendering, badge. No bundler.

Total ~90m. Parallelize where possible (e.g., scaffold UI while yt.ts is tested).

Explicitly deferred — not in MVP

  • Auth, persistence, DB, user accounts
  • Caching of transcripts/results
  • Non-English captions / auto-translation / language detection
  • Clip re-encoding options, thumbnails, waveform
  • Drag-and-drop, paste-anywhere, keyboard shortcuts
  • Rate-limit pre-check / cross-run daily quota tracking
  • Retry-with-repair for malformed JSON (would cost a second request)
  • Tests beyond the two tiny fixtures (parser + validator)
  • Docker / deploy, CI
  • Additional model routes beyond two fallbacks
  • Analytics, logging to disk, telemetry
